# ระบบเกมและวิธีเขียนเหตุการณ์ (YAML)

ตัวเลขสมดุลทั้งหมดอยู่ที่ `src/engine/balance.ts` ไฟล์เดียว ตัวอย่างการใช้งานจริงดูที่ `tests/fixtures/content/` (เนื้อหาทดสอบ ไม่ใช่ lore)

## Stat และชื่อ

id ในไฟล์ YAML ใช้ `STR DEX CON INT WIS CHA` ส่วนผู้เล่นเห็น กำลัง ว่องไว อึด ปัญญา ญาณ เสน่ห์ (`STAT_TH`)

## เผ่า (ได้จาก flag)

ตั้ง flag `race_human`, `race_elf`, `race_dwarf` หรือ `race_tiefling` ใน effects ตอนเกิด ระบบจะให้โบนัส SRD ครั้งเดียว สุ่มพ่อแม่และชื่อตัวละครจากกลุ่มชื่อของเผ่า (`content/names.yaml`) และให้สิ่งติดตัว `curse_brand` (ตราร้อน) กับทีฟลิ่ง กลุ่มชื่อใน `names.yaml` (`race:` คือ id กลุ่ม จะตั้งเป็นอะไรก็ได้ เช่น `temple_foundling`) มี `male`, `female` และ `surname` (ไม่บังคับ) ถ้าเผ่านั้นยังไม่มีกลุ่มชื่อ ชื่อจะเป็น "ผู้เดินทาง" และพ่อแม่เป็น "พ่อ" "แม่"

**เปลี่ยนกลุ่มชื่อตามบ้านที่เกิด** ใส่ `name_pool` ในตัวเลือกเกิดเดียวกับ flag เผ่า (ต้องตั้งพร้อมกัน เพราะชื่อสุ่มครั้งเดียว):

```yaml
effects:
  flags: [race_tiefling]
  name_pool: { self: temple_foundling, parents: none }   # none = ไม่มีพ่อแม่ที่รู้จัก ใช้ พ่อ แม่
```

`{surname}` ดึงจาก `surname` ของกลุ่มชื่อตัวเอง (ว่างถ้าไม่มี) ตัวตรวจเนื้อเรื่องเช็คว่ากลุ่มที่อ้างมีอยู่จริง

flag อื่นที่ขึ้นต้น `origin_` ใช้ได้อิสระ

## Effects ที่เพิ่มในรอบนี้

```yaml
effects:
  class: warrior | rogue | wizard | cleric | ranger | bard   # ครั้งแรกครั้งเดียว ให้ stat และ HP ตามตาราง
  god: verus | isel | talis | ossa | ulwen | belek | astel
  world: { gods: 1, demon: -1, star: 0 }      # คะแนนโลกลับ ผู้เล่นไม่เห็น (−20..20)
  alignment: { law: 2, moral: -1 }            # + คือระเบียบ/ดี  − คืออิสระ/ชั่ว (−10..10)
  reputation: { belek_bank: -2, wardens: 1 }  # ติดข้ามชีวิต (−10..10)
```

กลุ่มสำหรับ reputation: `crown lamp_church belek_bank royal_institute distillers dwarf_council star_hall wardens dock_rats ash_cult star_listeners`

## เงื่อนไข

ใช้ได้ทั้งใน `when` ของเหตุการณ์และ `requires` ของตัวเลือก: `class`, `god`, `world: {demon: [min, max]}`, `min_reputation`, `max_reputation`

เฉพาะ `when`: `age: [จาก, ถึง]` อ่านเป็น **อายุแบบมนุษย์** ทุกเผ่าโตเท่ากันจนอายุ 40 (`EVEN_AGING_UNTIL`) หลังจากนั้นร่างกายของเอลฟ์แก่ช้ากว่า 10 เท่า คนแคระ 5 เท่า (`ageScale` ใน balance.ts) เขียนเหตุการณ์ผู้ใหญ่ครั้งเดียวใช้ได้ทุกเผ่า ผู้เล่นเห็นอายุจริง · `year: [จาก, ถึง]` (ปีในโลก = ปีเกิด + อายุ ปีเกิดสุ่ม 270 ถึง 300) รายละเอียดเรื่องเวลาอยู่ในหัวข้อ "เวลาและชีวิตยาว"

## ข้อความ

- ตัวเลือกมี `text` ได้ แสดงหลังเลือก (ตัวเลือกที่มี check จะต่อกับ text ของ success/failure)
- ข้อความแบ่งย่อหน้าตามบรรทัดว่าง
- `{name}` `{surname}` `{father}` `{mother}` และ `{ชาย|หญิง}` เช่น `{เขา|เธอ}`
- `{partner}` `{p:เขา|เธอ}` คนรัก · `{child}` `{c:เขา|เธอ}` ลูกคนโตที่ยังอยู่ · `{newborn}` ลูกคนล่าสุดที่เข้ามาในครอบครัว · `{god}` เทพที่นับถือ · `{years}` จำนวนปีของเหตุการณ์หลายปี (เป็นคำ) · `{ชื่อบท}` กับ `{ชื่อบท:เขา|เธอ}` คนที่เล่นบทนั้น (ดู "ตัวแสดง")
- ค่า YAML ที่ขึ้นต้นด้วย `{` ต้องใส่เครื่องหมายคำพูด เช่น `mark: "{newborn}เกิด"`

## แนวทางและนักบวช

คะแนน alignment แบ่งเป็น 3 ช่องต่อแกน (ถึง ±3 คือเอียง) เทียบกับช่องของเทพบนตาราง 3×3 นักบวชที่ห่างเทพเกิน 1 ช่องเสียโบนัสญาณ ระบบตั้ง flag `cleric_drift` ให้ ใช้ใน `when.flags` เพื่อเขียนเหตุการณ์ "กลับตัว เปลี่ยนเทพ หรือหันไปหาสิ่งอื่น"

## รอยจอมมาร

สิ่งติดตัว `curse_brand` (ตราร้อน เซฟเก่าใช้ชื่อ `demon_mark`) ให้โบนัสทอยเมื่อ check มี `foe: demon` (ศัตรูลังเล) หรือ `foe: star` (ศัตรูมองไม่เห็น) ค่า `foe` อื่นไม่มีผล ตอนนี้เป็นสิ่งติดตัวในทะเบียนแล้ว ผลของมันจึงขึ้นในบรรทัดทอยเหมือนสิ่งติดตัวอื่น

## ชื่อเสียงข้ามชีวิต

เก็บใน `meta` แยกจากเซฟชีวิต ชีวิตใหม่เริ่มด้วยชื่อเสียงที่จบชีวิตก่อนทิ้งไว้ ปรับ `REPUTATION_CARRY` ใน balance.ts ถ้าอยากให้เลือนลง

## ตัวตรวจเนื้อเรื่อง (`npm run validate`)

จับ flag/trait ที่อ่านแต่ไม่เคยถูกตั้ง ของที่ไม่มีจริง ตัวเลือกไม่มีผล id ซ้ำ ช่วงอายุ/ปีกลับด้าน placeholder ที่พิมพ์ผิด flag `race_*` ที่ไม่มีเผ่า และกลุ่มชื่อของเผ่าที่ไม่มี ตั้ง `CONTENT_DIR=tests/fixtures/content` เพื่อตรวจ/รันด้วยเนื้อหาทดสอบ (`npm run dev:fixture`)

## ตัวละครตายก่อนอายุ 12 ไม่ได้

ก่อนอายุ `PROTECTED_AGE` (12) HP ไม่ต่ำกว่า 1 และ `die: true` ไม่มีผล ไม่ว่าเนื้อหาเขียนอะไร คนรอบตัวตายได้ตามเรื่อง (ผ่านข้อความและ flag ตามปกติ)

## เหตุการณ์ที่ต้องเกิด (`must: true`)

เหตุการณ์ปกติถูกสุ่มตามน้ำหนัก จึงอาจไม่ออกเลยตลอดช่วงอายุของมัน เรื่องที่ชีวิตต้องเจอให้ใส่ `must: true` (พิธีโตเป็นผู้ใหญ่ การเลือกอาชีพ หมายเกณฑ์ทหาร หมุดโลก ฉากปิดอายุสี่สิบ)

- ออกทันทีที่เข้าเงื่อนไข ก่อนเรื่องที่สุ่มทุกเรื่อง และไม่ใช้ตัวสุ่ม ชีวิตที่ seed เดียวกันจึงยังเดินเหมือนเดิมหลังจากนั้น
- ถ้าเข้าเงื่อนไขพร้อมกันหลายเรื่อง เรื่องที่เหลือโอกาสน้อยที่สุดออกก่อน (นับจาก `when.age` และ `when.year` เป็นจำนวนเหตุการณ์ที่เหลือ) เท่ากันให้ `weight` สูงกว่าออกก่อน
- ใช้กับ `once: false` ไม่ได้ และต้องมีเงื่อนไขอายุ ปี flag หรือ trait อย่างน้อยหนึ่งอย่าง ตัวตรวจจับให้ทั้งสองข้อ
- ปีหนึ่งออกได้เรื่องเดียว `must` สองเรื่องที่ถึงโอกาสสุดท้ายในปีเดียวกันจะเสียไปหนึ่งเรื่อง ให้เผื่อช่วงอายุหรือช่วงปีไว้อย่างน้อยสองปี (หมุดโลกใช้ `age: [19, 41]` เพื่อไม่ชนกับฉากปิดอายุสี่สิบ)

## เรื่องซ้ำและเหตุการณ์ที่ไม่มีตัวเลือก

- เหตุการณ์ `once: false` จะไม่ออกซ้ำภายใน `REPEAT_GAP` (5) เหตุการณ์ล่าสุด เว้นแต่ไม่มีเรื่องอื่นให้ออกเลย
- เหตุการณ์ที่ผู้เล่นคนนั้นเลือกอะไรไม่ได้สักข้อ (ทุกตัวเลือกติด `requires`) จะไม่ถูกหยิบมาแสดง เกมจึงไม่มีหน้าที่กดต่อไม่ได้
- เซฟเก่าที่ค้างอยู่ในเหตุการณ์ซึ่งไม่มีแล้วหรือเลือกไม่ได้ จะถูกพาไปเหตุการณ์ถัดไปตอนโหลด (`repairLife`)

## ตรวจชีวิตจำลอง (`npm run audit`)

เล่นชีวิตสุ่มบนเนื้อหาจริงแล้วพิมพ์รายงาน (ค่าเริ่มต้น 2,000 ชีวิต หรือ `npm run audit -- 500`) จบด้วยรหัส 1 ถ้าพบปัญหา `npm test` รันชุดเล็ก 400 ชีวิตทุกครั้ง

- ปัญหา: ทางตัน เหตุการณ์ที่ถูกหยิบผิดเงื่อนไขหรือเลือกไม่ได้ `must` ที่หลุด เรื่องอื่นออกทั้งที่ `must` รออยู่ เรื่องซ้ำเร็วทั้งที่มีเรื่องอื่น ข้อความที่พูดถึงคนที่ตายหรือไม่มีอยู่ ค่าสเตต HP หรือเงินที่เพี้ยน ประโยคสิ้นปีที่ซ้ำในชีวิตเดียว ความตายที่ไม่มีประโยคสุดท้ายหรือไม่มีป้ายบนเส้นชีวิต และคนรอบตัวที่อายุเกิน 125 แล้วยังอยู่
- ตัวเลขสมดุล: สาเหตุการตาย เหตุการณ์ที่ไม่มีใครเห็น จำนวนเรื่องให้สุ่มในแต่ละอายุ และสองชีวิตเจอเรื่องซ้ำกันกี่เปอร์เซ็นต์ (ใช้วัดความหลากหลายก่อนและหลังเพิ่มเนื้อหา)
- หัวข้อ "ชีวิตยาว": อายุขัยต่อเผ่า ฉากตายที่ได้ออกและที่ยังไม่มีใครเห็น คู่ครองกับลูก สิ่งติดตัวที่ได้บ่อย (แยกอย่างที่เนื้อเรื่องยังไม่มีทางให้ออกจากอย่างที่มีทางได้แต่ไม่มีใครได้) ตัวเลือกที่สิ่งติดตัวปิด เหตุการณ์หลายปี และป้ายบนเส้นชีวิต
- `tests/audit.test.ts` คุมเป้าสมดุลของชีวิตยาวด้วย: อายุขัยมนุษย์ (ข้อ D2) สัดส่วนที่ตายเพราะสิ้นอายุขัย นิสัยที่ไม่ควรติดเกินครึ่งของชีวิต และเพื่อนกับคู่แค้นที่ต้องมีทั้งคนที่ไปก่อนและคนที่อยู่ถึงวันสุดท้าย เนื้อหาชุดใหม่ที่ทำให้เลขหลุดช่วงจะทำให้เทสต์แดง
- เขียนเหตุการณ์ชุดใหม่แล้วให้รันทุกครั้งก่อนเปิด PR

# ชุด 1 รากของชีวิตยาว

ระบบที่เพิ่มเพื่อให้ชีวิตหนึ่งเล่นได้ตั้งแต่เกิดจนสิ้นอายุขัย ตัวอย่างการใช้จริงทุกข้อดูได้ใน `content/events/95_deaths.yaml` ถึง `99_elder.yaml` และ `tests/long-life.test.ts`

## เวลาและชีวิตยาว

- เวลาของโลกเดินเท่ากันทุกเผ่า เหตุการณ์หนึ่งเรื่องคือหนึ่งปี (ข้อ D3 ของแผนชีวิต 100 ปี แก้ L15 เดิม) เผ่าอายุยืนต่างกันแค่ร่างกายแก่ช้าหลังอายุ 40
- เรื่องเล่าจบที่ปี `STORY_END_YEAR` (410) ชีวิตที่ยังอยู่หลังปีนั้นจบแบบ "เรื่องยังไม่จบ" เอลฟ์กับคนแคระจึงยังไม่ถึงวัยชราในเนื้อหาตอนนี้
- **เหตุการณ์หลายปี** ใส่ `years: 3` เวลาจะเดินสามปีในเหตุการณ์เดียว ข้อความใช้ `{years}` แทนจำนวนปี เพราะระบบตัดให้สั้นลงเองเมื่อจะข้ามหมุดของโลก ข้ามปี 410 หรือข้ามเข้าวัยที่ต้องเช็คฤดูหนาว ถ้าเรื่องต้องใช้เวลานานจริงใส่ `min_years` ด้วย เหตุการณ์จะไม่ออกเมื่อเวลาที่เดินได้สั้นกว่านั้น
- **เหตุการณ์สำรอง** `fallback: true` ออกเฉพาะปีที่เรื่องปกติที่ออกได้มีน้อยกว่า `THIN_POOL` (3) ใช้เติมช่วงอายุที่เนื้อเรื่องยังบาง พอชุดถัดไปเขียนช่วงนั้นแน่นขึ้น เรื่องสำรองจะถอยไปเอง

## สิ้นปี: ฟื้น โรย ฤดูหนาว และข่าวของคนรอบตัว

ทุกปีหลังเหตุการณ์จบ ระบบทำสี่อย่างตามลำดับและจดลงบันทึกของปีนั้น (`entry.year`)

1. **ฟื้น** พลังชีวิตฟื้นเองตามวัย (`HP_REGEN`: ปีละ 3 ตั้งแต่ 18, 2 ตั้งแต่ 50, 1 ตั้งแต่ 65, ไม่ฟื้นเองหลัง 80) เด็กกับวัยรุ่นไม่ฟื้นเอง
2. **ร่างกายโรย** ตั้งแต่ 50 กำลังกับว่องไวมีโอกาสลด 1 ทุกปี (`DECLINE`) ไม่ต่ำกว่า 3 ปัญญา ญาณ และเสน่ห์ไม่ลดเอง
3. **เช็คฤดูหนาว** ตั้งแต่ 65 (ทีฟลิ่ง 70) ทอย d20 + อึด + สิ่งติดตัว + 2 ถ้ามีคู่ครองหรือลูกที่สนิทดูแล เทียบความยากที่เริ่มจาก 7 แล้วเพิ่ม 1 ทุก 3 ปี ตั้งแต่อายุ 83 เพิ่มช้าลงเป็นทุก 8 ปี และตั้งแต่ 100 เพิ่มทุก 2 ปี พลาดแล้วพลังชีวิตสูงสุดลดถาวร 2 พลังชีวิตสูงสุดหมดคือสิ้นอายุขัย (`WINTER`) หน้าจอใช้บรรทัดทอยเดิม
4. **คนรอบตัวจากไป** คนที่อายุเกิน 60 มีโอกาสจากไปทุกปีและมากขึ้นตามวัย (`NPC_DEATH`) ข่าวมาเป็นประโยคเดียวท้ายบันทึก

เป้าของตัวเลข (เล่นสุ่ม 2,000 ชีวิต): มนุษย์ที่อยู่ถึงวัยชราสิ้นอายุขัยกลางๆ ที่ 89 เกือบครึ่งไปในช่วง 80 ถึง 90 ราวหนึ่งในสิบไปก่อน 80 และราวหนึ่งในเจ็ดอยู่ถึง 100 ทีฟลิ่งยืนกว่าราวสี่ปี คนรอบตัวครึ่งหนึ่งอยู่ถึงราว 81

**ประโยคสิ้นปี** อยู่ใน `content/lines.yaml` ระบบหากุญแจที่ตรงที่สุดก่อน (`decline_STR` แล้ว `decline` · `news_death_<ตำแหน่งในครอบครัว>` แล้ว `news_death_<ชนิดความสัมพันธ์>` แล้ว `news_death` · `winter_fail`) ประโยคเดิมไม่ออกซ้ำในชีวิตเดียว ประโยคหมดก็เงียบ ยกเว้นข่าวการตายที่ต้องบอกเสมอ จึงควรมีหลายประโยคต่อกุญแจ

## คนในชีวิต และตัวแสดงของเหตุการณ์

คนทุกคนในผังมีปีเกิด (`born`) เนื้อหาใส่ `age:` ตอนพาเข้ามาได้ ไม่ใส่ระบบกะจากบทบาท (พ่อแม่แก่กว่า 20 ถึง 34 ปี เพื่อนกับคู่แค้นรุ่นเดียวกัน) อายุของทุกคนเดินตามปีของโลก

```yaml
- id: elder.passing_friend
  cast:
    pal: { bond: [friend], min_age: 70, min_closeness: 1 }   # ต้องมีคนจริงเข้าบท ไม่มีก็ไม่ออก
  people: [{ id: "@pal", dies: true }]                        # ใช้ก่อนผลของตัวเลือก ไม่ว่าเลือกทางไหน
  mark: "{pal}จากไป"
  text: |
    {pal}ตายเมื่อสามวันก่อน ... ญาติของ{pal:เขา|นาง}จัดเลี้ยงส่งที่ร้านเหล้า
```

- `cast` บอกว่าเหตุการณ์ต้องการคนแบบไหน: `id`, `kin`, `bond`, `min_closeness`, `max_closeness`, `min_age`, `max_age` (อายุเทียบมนุษย์), `alive: false` (คนที่จากไปแล้ว ใช้กับเรื่องรำลึก), `pick` (`closest` `eldest` `youngest` `first` `random`) และ `optional: true` (ไม่มีคนเข้าบทก็ยังออกได้ แต่ใช้ชื่อบทได้เฉพาะในตัวเลือกที่มี `requires.cast`)
- ใน `effects.people` อ้างคนในบทด้วย `id: "@ชื่อบท"`
- **ลูก** ใช้ `effects: { child: {} }` ระบบตั้งชื่อจากกลุ่มชื่อของบ้าน สุ่มเพศ และใส่ลงผังเป็นคนจริง (`kin: child`) เหตุการณ์ที่ให้ลูกต้องกันด้วย flag `married` เอง (ตัวตรวจชีวิตจำลองนับลูกที่เกิดโดยไม่ได้แต่งงาน ต้องเป็นศูนย์)
- **คู่ครอง** อยู่ในผังด้วย id `partner` ก่อนอายุ 100 คู่ครองไม่จากไปด้วยการทอยประจำปี ถ้าจะไปก่อนต้องเป็นฉากที่เขียนไว้ ไม่อย่างนั้นอยู่จนถึงวันที่ตัวละครจากไป
- **คนสำคัญรอฉากลา** พ่อ แม่ คนที่สนิทตั้งแต่ 3 และคนที่เนื้อเรื่องเขียนฉากตายไว้ให้ (`people: [{ id: kedra, dies: true }]` ที่ไหนสักแห่ง) ระบบไม่เอาไปเงียบๆ จนกว่าจะอายุ 88
- flag ที่ระบบตั้งให้เอง: `has_partner`, `partner_died`, `father_died`, `mother_died` ฉากที่มี `{father}` ให้กันด้วย `not_flags: [father_away, father_lost]` เหมือนเดิม ข้อความที่เอ่ยถึงคนที่ไม่อยู่แล้วระบบไม่หยิบมาแสดง

## ความตายและฉากตาย

ตัวละครไม่ตายทันที พอพลังชีวิตหมด ผลของตัวเลือกมี `die` หรือพลังชีวิตสูงสุดหมดเพราะฤดูหนาว เวลาหยุดที่ปีนั้นและเหตุการณ์ถัดไปคือ **ฉากตาย** (`stage: death`) เลือกในฉากนั้นแล้วชีวิตจึงจบ

```yaml
- id: death.age_partner
  stage: death
  mark: ฤดูหนาวสุดท้าย            # ป้ายสุดท้ายบนเส้นชีวิต ทุกทางออกของฉากตายต้องมี (ตัวตรวจบังคับ)
  when:
    dying: [age]                 # age สิ้นอายุขัย · wound แผล · fight การปะทะ (เช็คที่มี foe) · sacrifice (die: sacrifice)
    told: false                  # false = ยังไม่มีใครเล่าความตาย ฉากนี้ต้องเล่าเอง · true = ผลที่มี die เล่าไปแล้ว ฉากนี้เล่าจากข้างใน
    flags: [has_partner]
  choices:
    - id: hold_hand
      effects: { epitaph: "..." }   # ประโยคสุดท้ายของชีวิต ขึ้นใต้ชื่อในหน้าชีวประวัติ ทุกทางออกต้องมี ยกเว้นทางที่รอด
```

- ฉากตายที่ให้รอดได้ใส่ `survive: true` ในผลของตัวเลือก (ข้อเสนอของเสียงใต้ดิน ปาฏิหาริย์) คนที่กำลังสิ้นอายุขัยต้องได้ `max_hp` คืนในผลเดียวกัน
- สิ่งติดตัวที่มีผล `cheat_death` กันตายได้หนึ่งครั้งก่อนถึงฉากตาย (ไม่กันสิ้นอายุขัย)
- หน้าจอ: ฉากมืดลงไม่มีตัวละคร บันทึกปิดด้วยปีเกิดถึงปีตาย มีแผ่นปิดท้ายพร้อมปุ่มอ่านชีวประวัติ หน้าชีวประวัติแสดงภาพ ปี ประโยคสุดท้าย เส้นชีวิต สิ่งติดตัว คนที่อยู่ข้างหลัง และของที่ทิ้งไว้

## ป้ายบนเส้นชีวิต (`mark`)

เหตุการณ์ที่ควรขึ้นเส้นชีวิตในหน้าชีวประวัติใส่ `mark:` สั้นๆ ที่ระดับเหตุการณ์ ตัวเลือก (`effects.mark`) หรือผลสำเร็จกับล้มเหลว ระบบใช้ป้ายที่เจาะจงที่สุด (ผล แล้วตัวเลือก แล้วเหตุการณ์) ใช้ชื่อบทและ `{newborn}` ได้ เหตุการณ์ของโลก (id ที่มี `.world_` เช่น `adult.world_king_dies`) ขึ้นเป็นสีเน้น

## สิ่งติดตัว (`content/traits.yaml`)

ทะเบียนเดียวของพร คำสาป ลักษณะ และแผล 60 อย่าง ไอคอนอยู่ที่ `public/icons/trait_<id>.png` ตอนนี้เนื้อเรื่องให้ได้จริง 21 อย่าง (พร 2 คำสาป 1 ลักษณะ 13 แผล 5) ที่เหลือรอชุดที่มีที่มาของมัน (การปะทะ เทพ เจ้าเดิม ผู้อยู่นอกฟ้า) รายงานตัวตรวจชีวิตจำลองบอกจำนวนนี้ทุกครั้ง

- ให้และถอด: `effects: { traits: [id], lose_traits: [id], trait_step: { id: 1 } }` (ขั้นของสิ่งติดตัวที่ลุกลามได้ บวกคือลุกลาม ลบคือทุเลา)
- เงื่อนไข: `when.trait`, `requires.trait`, `not_traits: [...]` (ใช้ได้ทั้ง `when` และ `requires`) และ `big_room: true` สำหรับเหตุการณ์ที่ให้พรหรือคำสาปใหญ่ (ถือได้ไม่เกิน 2)
- ผลที่ระบบคิดให้ (`effects` ในทะเบียน): `check_bonus` (เจาะจง `stats`, `foes`, `locations` ได้), `max_hp`, `regen`, `winter`, `ageless`, `cheat_death` ผลต่อการทอยขึ้นในบรรทัดทอยพร้อมชื่อสิ่งติดตัว (`roll.traits`)
- บรรทัดใน `gives` กับ `costs` ที่ระบบไม่ได้คิดให้ เหตุการณ์ต้องเคารพเองด้วย `requires` ห้ามเขียนราคาที่ไม่มีผลจริง
- กติกาของโลกที่ตัวตรวจบังคับ: พรทุกอย่างมีราคาหรือเงื่อนไข (`costs` หรือ `breaks`) คำสาปทุกอย่างมีของแถม (`gives`) ทางแก้อย่างน้อยสองทาง (`cures`) และทางอยู่กับมัน (`live_with`)

**นิสัย** ตัวเลือกติดป้าย `habit: <id>` ได้ (id ของลักษณะที่มี `habit: true`) ลักษณะนั้นติดตัวเมื่อ

1. เลือกทางของนิสัยนั้นครบ `HABIT_COUNT` (3) ครั้ง และ
2. เลือกไม่น้อยกว่าครึ่ง (`HABIT_SHARE`) ของครั้งที่ทางนั้นมีให้เลือก คนที่เลือกทางดื้อสามครั้งในร้อยปีจึงไม่ใช่คนหัวแข็ง

นับเฉพาะครั้งแรกที่เจอแต่ละเหตุการณ์ (เรื่องที่เวียนกลับมาไม่นับเพิ่ม) ตัวเลือกที่ถูกซ่อนไม่นับว่ามีให้เลือก ชีวิตหนึ่งมีลักษณะจากนิสัยได้ไม่เกิน 3 และลักษณะตรงข้ามกัน (`excludes`) ไม่ก่อตัวทั้งคู่

**สิ่งติดตัวที่ปิดตัวเลือก** มีสองทาง หน้าจอแสดงตัวเลือกนั้นเป็นล็อกพร้อมชื่อสิ่งติดตัว (ไม่ซ่อน) ทั้งสองทาง

- `blocks: [<id นิสัย>]` ในทะเบียน: คนที่ถือสิ่งนี้เลือกทางที่ติดป้ายนิสัยนั้นไม่ได้อีก (คนหัวแข็งเลือกทางขี้ขลาดไม่ได้) ต้องเขียนราคานี้ไว้ใน `costs` ด้วย
- `requires: { not_traits: [curious] }` ที่ตัวเลือก: ปิดเฉพาะตัวเลือกนั้น
- ตัวตรวจจับเหตุการณ์ที่สิ่งติดตัวอย่างเดียวปิดตัวเลือกได้ทุกข้อ

## เซฟ

เซฟรุ่น 3 `migrate` เติมช่องใหม่จากค่าเริ่มต้นของ `newLife` (`traitSteps`, `habits`, `habitOffers`, `dying`, `deathCause`, `epitaph`, `cast`) เปลี่ยนรหัสสิ่งติดตัวรุ่นเก่า (`TRAIT_RENAMES`) และกะปีเกิดให้คนในผังที่ยังไม่มี
